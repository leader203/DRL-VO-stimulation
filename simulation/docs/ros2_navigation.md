# ROS 2 行人导航

本方案让独立 ROS 进程拥有路线、避碰和人物运动积分，Isaac Sim 基本应用拥有场景、PhysX、角色根位姿写入与动画显示。
不启用 IRA、`omni.anim.behavior.core` 或 `omni.anim.navigation.core`，不生成或查询 NavMesh。
人物动作库经独立重定向用于视觉；使用动作库不等于启用原生行人控制器。

## 启动

完整自动流程可使用 `run.py workflow PROJECT --record`，由父进程只为原生子进程加载 ROS setup；
它依次运行、核对坐标并评估，见[自动工作流](workflow.md#自动运行核对与评估)。
直接运行时从仓库根目录执行：

```bash
source /opt/ros/jazzy/setup.bash
UV_PROJECT_ENVIRONMENT=env_isaaclab uv run --no-sync python \
  src/pedstrain_simulation/simulation/run.py run \
  src/pedstrain_simulation/simulation/configs/third_3
```

启动启用行人的场景需要 ROS Jazzy 的 `rclpy`、标准消息和可用的 `g++`。默认动作库和[角色清单](pedestrian_yaml.md#角色资源清单)都需要本地 `asset_root`。也可在场景中指定自己的 `pedestrians.motion_library`。
程序在运行输出目录中编译仓库随附的 CPU RVO2 C ABI，不自动安装依赖，也不要求启动 Nav2 服务。
不要在已运行的 Isaac 进程内修改 ROS 库路径来修复装载错误；应在正确加载 ROS 的 shell 中重新启动。

`simulation.duration` 始终是仿真秒。控制频率来自 `control_hz`，墙钟耗时由地图生成、渲染、DDS 往返及计算性能决定。
会话使用 loop-isaac 的双精度手动秒步驱动控制时钟，独立于 USD 的 FPS/TCPS；不修改源动画时间码。
仅设置目标帧率不能替代这个步长控制。暂停期间不推进物理，关闭会话时恢复原 loop/player 设置。
ROS 控制台支持 `play`、`pause`、`status`、`quit`；运行中时间轴回退会报错，重置计划需重新创建会话。
`headless: true` 只隐藏窗口；纯仿真可另设 `render_viewport: false`，不能用无视口结果验证可见步态。
运行中的地图、路径、实测行人、障碍和门状态可用 [RViz2 监控入口](rviz_monitoring.md) 查看。

## 配置

场景与人口使用 `schema_version: 1`，导航参数由独立设置文件选择。

```yaml
navigation:
  backend: ros2
  waypoint_frame: stage_world
  settings_path: navigation_settings.yaml
```

CLI `init` 默认生成上述两文件 ROS 工程；`--navigation-settings FILE` 引用现有参数，不复制。
CLI 新 ROS 项目默认 `waypoint_frame: stage_world`，可用 `init --waypoint-frame world_m` 选择规范米制输入。
Python 创建工程时可以用 `waypoint_frame="stage_world"` 选择舞台 WORLD 坐标。
不传 `settings_path` 时，ROS 后端读取[包级设置](../configs/runtime/ros2_navigation.yaml)。
自己的文件中遗漏字段使用[类型默认值](../configuration/navigation.py)，不逐字段合并包级文件。
可复制当前设置文件、在副本里调参，然后用 `run PROJECT --dry-run --navigation-settings FILE` 检查选中参数。
去掉 `--dry-run` 即按同样选择启动，或用 `workflow PROJECT --navigation-settings FILE` 把该文件纳入自动验收。
命令行文件路径相对终端当前目录，项目 YAML/TOML 内的 `navigation.settings_path` 相对声明文件。
临时选项整体替换导航设置文件，只适用于启用了行人的 ROS 2 项目。持久采用这份参数时，修改 `navigation.settings_path`。
仓库的 `third`、`third_2`、`third_exp`、`third_3` 已显式选择 ROS2，并通过
`../runtime/ros2_navigation.yaml` 共享导航参数；各自原始计划、时长、种子、物理和场景设置保留。

导航设置采用平铺映射。下面的片段只展示常用字段。调参时复制项目当前使用的完整文件，保留既有返程朝向策略。
场景未显式设置 `pedestrians.motion_library` 时，导航文件还需要提供本机的 `asset_root`。

```yaml
resolution_m: 0.02
body_radius_m: 0.25
body_height_m: 1.8
map_clearance_m: 0.0275
preferred_path_clearance_m: 0.05
pair_clearance_m: 0.225
spawn_tolerance_m: 0.0
goal_projection_tolerance_m: null
max_yield_distance_m: 0.4
origin_m: [0.0, 0.0, 0.0]
yaw_rad: 0.0
floor_height_m: 0.0
bounds_m: null
control_hz: 60
time_horizon_s: 2.5
obstacle_time_horizon_s: 0.5
neighbor_distance_m: 4.8
ros_setup_path: /opt/ros/jazzy/setup.bash
ros_namespace: /pedestrian_sim
ros_domain_id: 37
```

| 字段组 | 作用 |
|---|---|
| `resolution_m`、`bounds_m`、`max_cells` | 地图精度、ROS 平面范围 `[xmin,ymin,xmax,ymax]` 与内存/查询预算 |
| `floor_height_m`、`floor_tolerance_m`、`floor_clearance_m`、`max_slope_deg` | 单层地面支撑与人体高度带；无支撑不判为 free |
| `body_radius_m`、`body_height_m` | 实际 PhysX 胶囊的半径和总高 [m]。共享配置为 `0.25` 和 `1.8` |
| `map_clearance_m` | 身体与场景几何之间的额外边距 [m]。共享配置为 `0.0275`，供规划、站位、执行扫掠和门扇检查使用 |
| `preferred_path_clearance_m` | 路径规划和前瞻的额外净空偏好 [m]。共享文件用 `0.05`，外部配置省略时为 `0.0` |
| `spawn_tolerance_m` | 无效固定出生点的可选水平修正半径 [m]，默认 `0.0`，保留精确出生请求 |
| `goal_projection_tolerance_m` | A* 目标需投影时的水平误差上限 [m]，`null` 使用原路点的有效平面到达范围 |
| `max_yield_distance_m` | 门前、目标排队和相向交会临时让位距起点的最大位移 [m]，默认 `0.4` |
| `pair_clearance_m`、`time_horizon_s`、`obstacle_time_horizon_s`、`neighbor_distance_m`、`relaxation_time_s` | 行人间净距 [m]、行人/障碍分别预测的时间 [s]、邻域 [m] 与 SFM 松弛时间 [s] |
| `max_turn_rate_radps`、`control_hz` | 朝向速度上限 [rad/s] 与批次频率 [Hz] |
| `auto_return_heading` | 自动返程点朝向：`preserve`复制去程yaw；`follow_route`取消该强制yaw，让实际返程行进方向决定朝向 |
| `origin_m`、`yaw_rad` | ROS map 原点在规范世界中的位置 [m] 与 map 轴偏航 [rad] |
| `dynamic_roots` | 额外的脚本驱动对象根；对象路径属于场景配置，不写进通用算法 |
| `asset_root` | 默认动作库和角色清单的本地资产根 |
| `ros_setup_path`、`ros_namespace`、`ros_domain_id`、`request_timeout_s` | 启动环境、topic 前缀、DDS domain 与请求墙钟超时 [s] |

包级配置使用 2 厘米栅格，减少地面边界取整造成的伪不可达；精细地图增加启动查询和内存成本，仍受 `max_cells` 限制。
共享 ROS 设置的有效障碍净空半径为 `body_radius_m + map_clearance_m = 0.2775 m`。采用额外路径偏好时为 `0.3275 m`，受限区域可回到 `0.2775 m`。
额外场景边距用于静态地图规划、站位检查，以及多边形障碍和门扇的扫掠检查。
显式自定义导航文件省略该字段时仍取类型默认 `0.03 m`。
行人间目标中心距由 `2 * body_radius_m + pair_clearance_m` 独立计算。在共享配置中，身体表面目标净距为 `0.225 m`，标准角色的目标中心距为 `0.725 m`。
自定义文件省略 `pair_clearance_m` 时仍使用类型默认 `0.25 m`。实际身体重叠检查使用两人的物理半径。
预检 JSON 的 `ros2_clearance` 以米列出上述两个规划半径、固定出生的身体接触阈值 `2 * body_radius_m`，以及行人间目标中心距。
固定出生点的实际间距由 `fixed_spawn_check` 另外报告。最终导航参数文件见 `dependencies.pedestrian_settings`。
原 YAML 的出生点、路点、速度、开始时间、逐点朝向/停留、往返和到达容差保留。
共享ROS配置已选 `auto_return_heading: follow_route`，新生成工程也会复制该策略。
它只影响 `repeat: true` 且最后一个显式路点不等于出生点时自动追加的反向路段；原显式去程和显式闭合路线的yaw不变，所有位置与停留不变。
外部设置文件省略该字段、直接构造设置或直接调用引擎时仍默认 `preserve`；需要旧复制朝向行为可显式设置该值。
无明确出生坐标时，在身体可通过的空闲格上采样；规划内部终点只能在原到达容差内选择，不改写用户 YAML 或扩大容差。
明确出生点在创建角色和 ROS 资源前检查静态净空、当前实体轮廓和身体重叠。仅显式启用 `spawn_tolerance_m` 且原请求不安全时，
才从该半径内按距离搜索已认证的栅格中心，高度不变。出生修正不改写 YAML，bootstrap 和坐标回执分别记录原请求、实际出生点与位移。
出生修正保留作者明确指定的闭环路线。自动生成的返程以实际出生点为返回目标。
所有路点仍按原三维 `arrival_tolerance` 判断。A* 投影上限只会缩小投影搜索范围，已经实际进入原到达球的角色仍按原规则到达。
身体重叠与舒适净距不足分别处理：固定点仅因舒适净距不足不会被当作物理重叠拒绝，随机点仍保留原间距规则。

普通路径先认证实际位置到附近格点的完整圆盘连接；只有原起点连接集为空时，才在身体净空半径内作一次有界扩大搜索。
已在原到达球内且当前位置安全时返回零运动路径，不强迫继续走到目标中心。八邻域、禁止切角、未知格阻挡及整段净空检查保留。
对于重复目标，静态地图会复用已经过扫掠验证的到达区域。缓存按目标、容差、净空和地图几何区分，最多保留 16 项，每项最多缓存 4096 个栅格锚点。
动态障碍或行人的占用可能影响到达区域时，使用当前覆盖几何重新检查。到达仍按原三维容差判定。
启用额外净空偏好后，若有可认证且绕行增加不超过一个身体直径的路径，规划器会优先采用它，并在路径捷径及前瞻中保留该余量。
遇到窄通道、贴墙起点或动态障碍导致偏好不可行时，按原硬净空重新规划。
重复让位规划先按栅格连通性排除起点和目标不连通的候选。可达候选仍按原顺序进行 A* 和完整身体扫掠认证。

接近规划器生成的中间拐角时，引导可提前延伸到下一条路径边上的可见点。
前瞻距离由原速度、松弛时间和最大角速度计算，每条捷径仍认证完整身体圆盘与当前规划障碍；
看不到下一段时保留原顶点。这避免追逐顶点最后几毫米再反向转回后续路线。
若缓存中的中间拐点失去出弯前瞻，且继续追踪该点会使速度上限明显低于实测速度，控制器可从实测位置限次重规划。
只有新引导保留原净空、取得可扫掠的出弯前瞻且所需转角更小时才采用。每次尝试后，行人需移动至少一个身体半径才可再次尝试。
它不改变 YAML 业务路点、到达球、指定朝向或停留。
漫游先筛原1–4m范围，再随机规划；首个尝试失败后按实际起点的栅格可达分量筛选，仍最多128次规划尝试。
缺少可认证格点连接时保留连续直线路径尝试，有限栅格/采样不能被解释为连续空间完备性证明。
低速进度检查点为一秒名义行程与5cm中的较小值，真实无进展仍按原12仿真秒期限失败，不改用户速度。

普通路径与非射线的临时点跟踪会按当前位置、朝向和转向速度限制执行速度：
到局部目标的切圆曲率为 `2*sin(朝向偏差)/距离`，转弯半径不足时先减速，避免在近点周围持续绕行。
普通行走已通过扫掠检查的出弯前瞻点属于连续路径引导。该段沿用原速度、可转扇区和单步距离限制，精确到点制动用于真实到达点及临时目标。
接近规划拐点时，若当前候选速度较快、偏离引导方向且前方扫掠会遇到墙体，控制器先尝试朝清晰的路径段转向。
当前转角内找不到可通行速度时，可在通过动态安全检查的位置停步转向，给后续拐弯保留空间。
原 SFM 目标吸引保持，实际候选仍经过同一 RVO2、角速、静态／动态和行人扫掠净空检查；
已认证路径的软墙力只保留沿引导方向的正向分量，避免横向壁力与全局路径竞争而诱导长向转身。
SFM行人作用力与通行偏好仍保留；侧向静态净空继续由身体膨胀地图、RVO2约束和完整扫掠检查维护。
直线路段上两人相向接近时，若侧移的前瞻路径会进入墙面净空、沿路线前方仍有空间，控制器会用墙面的横向作用力减弱朝墙的侧移。
修正后的速度偏好仍交给 RVO2，并按实际运动扫掠检查障碍物和行人净距。
对齐后可恢复原速度并在合法单步内到达，不对每个中间点额外施加指数减速。
已认证的退让射线保留原先转向再移动的控制。原路点到达朝向、停留和往返语义保持，
这些必要转向仍会出现，不能将它们与近点追逐造成的反复转动混为一谈。
近点若经ORCA投影后的前向进度低于执行上限的25%，恢复查询使用有界位置误差偏好，避免横向惯性在墙边法向限速时反复摆头。
远段仍保留原SFM偏好和RVO转向引导。末段已走完的精确零长度节点会被消费；微小、可执行的最后一弦仍经完整检查后有限到点。
已经开始的停车转向会锁定引导朝向，完成后才恢复平移，并扣除本步已用角度；极小非零速度候选不会反复打断它。
若外部动态障碍使原地等待在下一步不安全，则解除锁定并保留原RVO避险能力。
停步时还会在同一RVO2约束内查询转角更小的可行方向；只有完整位移段证书和当前执行转向扇区都允许时才执行替代速度，否则仅作为转向引导。
原解已经沿路线正向且下一步位移可表示时，不用靠近当前身体面向的纯切向候选替换它；
真正受约束的非共线解、零解和数值上不能产生位移的解仍保留原恢复查询。
普通门前让位仅在整条让位线对静态／行人净空和所有实测外部障碍在原剩余期限内的扫掠均安全时使用认证射线，
避免在固定让位点附近反复侧向纠偏。未知运动或扫掠冲突保留普通RVO逃逸，不延长原门控期限。

## 控制责任与协议

| 部分 | 唯一职责 |
|---|---|
| `planner.py` | 带身体半径和未知格边界的栅格 A*、路径简化及整段净空检查 |
| ROS 节点中的 `solver.py` | YAML 时间调度、SFM 期望速度、随附 RVO2 求解、转向限制和位置积分 |
| ROS 节点中的 `interactions.py` | 门与路线协作、有限退让、扫掠区清空确认和开关门授权 |
| ROS 节点中的 `goal_occupancy.py` | 原目标区域占用、排队位置与离开通道优先权 |
| `transport.py` | 真实 DDS 通信、仿真时钟、有序完整批次及超时处理，不做本地规划 |
| Isaac 中的 `actors.py` | 核对完整命令，唯一写入角色根位姿，按实际距离播放步态 |
| `mapping.py` / `doors.py` | 物理地图和实时障碍观测；元数据门关节驱动，不写行人姿态 |

每次运行的 namespace 为配置前缀加 `session_<随机后缀>`，实际值见报告的 `ros_namespace`。

| Topic | 消息与语义 |
|---|---|
| `/clock` | `rosgraph_msgs/Clock`，仿真时间；同一 domain 应只有一个仿真时钟所有者 |
| `<namespace>/map` | `nav_msgs/OccupancyGrid`，可靠、transient-local，frame 为 `map` |
| `<namespace>/<name>/path` | `nav_msgs/Path`，常规栅格路径变化时发布；临时让行状态另见 `passing` |
| `<namespace>/markers` | `visualization_msgs/MarkerArray`，最多 10Hz 的实测状态及明确分开的请求/指令诊断 |
| `<namespace>/state` | `std_msgs/String` JSON：`sequence`、`time_s`、`dt`、完整 `agents`、`obstacles` 和 `doors` 观测 |
| `<namespace>/command` | `std_msgs/String` JSON：相同 `sequence` 的完整 `agents`、`door_commands`、`passing` 摘要，或明确错误 |

每个仿真 tick 等待对应回复；重发使用完全相同的序列与快照，节点返回缓存结果，不重复积分。
新的序列必须严格推进非负、有限的数值 `time_s`，正数 `dt` 要匹配相邻成功请求的仿真时间增量；布尔值和字符串不作为时间数值。
首个请求允许非零启动时刻，不要求该时刻等于 `dt`。DDS时间回退需重建会话；纯Python引擎的原重置接口保持独立。
成功回复同时匹配序号与本次时间，时间不符的回复不会应用到角色；旧版无时间戳的明确失败回复仍能及时传递。
角色命令的 `phase` 表示当前执行阶段，`route_phase` 保留原路线调度阶段；临时让位不推进路点索引或循环次数。
只读 `guidance` 给出当前请求引导点 [m] 和阶段，不代替批次中的实际执行位置。
状态错误、角色缺失、未知动态速度或超时会明确失败。此协议不是 Nav2 动作接口，也不是机器人速度话题接管。
用 `ros2` CLI 观察时，`ROS_DOMAIN_ID` 需与配置一致；读取只发布一次的地图/路径需使用 transient-local 订阅。
Path和Marker属于只读观测。发布失败只记录告警，不会在控制成功后追加导航错误，也不改变导航状态；Path缓存只在发布成功后更新，以便后续重试。

运行报告给出 `output_directory`，其下保存 `map.npz/pgm/yaml`、`bootstrap.json`、`trace.jsonl`、
`ros2_node.log`、`ros_logs/`、求解库和 `result.json`；`simulation.report_path` 可另保存最终摘要。
目录按每次运行生成新名字。报告还包含地图诊断、角色距离/步态相位、门控状态、被抑制的冲突脚本及资源清理结果。

## 静态地图与当前碰撞几何

`map.npz` 和 `OccupancyGrid` 是静态 PhysX 栅格；可移动刚体不会永久烘焙进这张图。
机器人与其他对象使用相同的真实碰撞体分类：已证明由不可断固定关节连接世界的刚体烘焙为静态障碍，
其余启用刚体逐次读取 PhysX 位姿。声明 `dynamic_roots` 时，子树中的碰撞体仍优先读取最近的启用刚体，
只有没有刚体的脚本对象才读取声明根的 USD 变换；显式动态子树不会被固定关节分类覆盖。
运行中静态碰撞体的成员集合发生变化会明确失败，要求重建地图与会话，避免继续使用过期地图。
预期由脚本移动的对象应在启动前声明 `dynamic_roots`；普通静态对象的运行期变形或移动不受自动重烘焙支持。
普通行走、漫游及目标协作规划同时查询当前实测的非受控刚体轮廓，避免出现“静态图是 free、真实实心门叶却挡路”的路线。
后续每段引导从实际位置重新检查；几何变化会使相应规划缓存失效。
无明确出生点时，随机采样还会检查当前身体高度带内的实际形状，不能只依赖静态 free 格。

只有启用的 `door_specs.body_prim_path` 及其子树由门控负责未来开门，才在全局规划层作此区分；
普通物体即使名称含 Door，也仍是实际障碍。实际 RVO2、完整运动弦检查及闭门/退让始终检查当前全部物体，
这项区分不会让行人穿过未打开的门。

同一静态目标的局部投影可作单目标有界缓存；仅当每层额外身体、物体和保护通道都明确远离目标局部区时复用。
近约束、未知栅格子类或不匹配的身体净空仍按原几何计算，完整路径仍须重新验证。

## 门与导航协作

Isaac 的 `Ros2Doors(..., navigation_interlock=True)` 从 `automaticDoor:joint` 及父级 `automaticDoor:*`
元数据生成 `settings.door_specs`：室内区域、真实关节框架和所有有效碰撞体的连续转动保守外包。
ROS `interactions.py` 根据实际身体、原目标与门的内外区域决定是否需要穿门，不按场景名或固定门名分支。
门运动的合成扫掠障碍保留已知实际高度带，不阻挡其他高度层的身体；高度未知或无效时仍保守阻挡。
首次准入要求身体中心到真实门口的距离不超过 USD `automaticDoor:approachDistance`，当前路线确实要穿门，
且实测身体正前方射线穿过有限门洞，同时与门洞中点的偏差位于 `automaticDoor:facingHalfAngle` 内。
若朝向不符，行人先原地朝门洞中点转向。完成安全让位后，首次实际开门会重查上述条件。
场景可用 `automaticDoor:requireFrontApproach` 启用门前站位检查。走廊侧行人的身体中心须投影在实际门洞内。需要穿门但尚未站在门前或仍处于门扇扫掠区时，先沿经净空检查的路线走到可安全开门的站位，再申请通行。
隔间内侧允许身体在门洞横向范围内有实际重叠，并可用 `automaticDoor:exitApproachDistance` 指定扫掠安全站位的最远实测距离 [m]。内侧申请和首次开门使用同一距离。两侧开启前都要通过有限门洞射线和朝向检查。
门扇开始转动后保留通行授权，直到身体通过并清空扫掠区。
源场景或覆盖层的旧门脚本不得并行驱动同一关节；验收时核对冲突脚本抑制记录和实际门观测。
启用 ROS 行人时，临时组合层从 `automaticDoor:joint` 建立控制器根集合，中和这些根内同时含
`automaticDoor:` 和 `DriveAPI` 的 `inputs:script`，不要求脚本导入行为或导航库。
这项门规则保留根外无关内联脚本，且不应用于无行人模式；原有 IRA/导航冲突抑制另行适用。
根外或经外部 helper 实现的门控制器不属于这项内联识别范围，仍需核对唯一驱动者并完成原生复验。

每批请求的 `doors` 包含 `name`、`valid`、`actual_angle_deg`、`angular_speed_degps`、`fully_open`、`fully_closed`。
开度来自真实 PhysX 刚体与关节框架；只有角度到位且相邻时刻测得角速度足够低才算开启。
Drive 目标到位、首次采样或无效读数都不能代替这个条件。
ROS 回复 `door_commands: [{name, hold, request_open}]`，Isaac 在回复后驱动下一物理步；
`hold` 优先于开门请求，保持当前实际开度，遗漏的门命令默认 hold。

完整扫掠区内有身体时先保持门，ROS 可让已开始行走的角色转向并退到距交互起点不超过 `max_yield_distance_m`
的临时安全点；路径仍须满足原身体半径、边距及其他障碍约束。
当前与前一控制批次均确认全扫掠区已清空，才授权开门；门运动期间规划使用完整扫掠外包。
临时交互切换时保留原全局路径，使门控仍能识别拐过门框后的穿门路线；恢复行走时从实际位置重新检查可见路段，必要时重规划。
等真实 `fully_open` 后继续原目标。当前路线上下文的通行授权在转向、开门和短暂离开触发半径时保留，
直到身体实际跨过 portal/室内外边界，且连续两次观测已清出完整扫掠区才释放；
授权超时或路线上下文变化独立处理，不反复续期。通行占用期间保持开门，清空后才允许关闭。
持有效出门授权的行人在门已实测打开后先清出扫掠区，再参与门外的目标排队或跟随等待。此优先权保留普通路径和运动检查。
若尚未跨过门洞且同门进场者占据出门目标，继续由门内外交换流程分配让位。
临时 `door_face`、`door_yield` 和 `door_wait` 保留 YAML 路点、停留、朝向和到达容差。

到达球边缘可能落在门扇扫掠区内，而配置路点在室内更深处。若首次进入到达球的位置无法在让位预算内安全关门，
系统可在开始驻留前沿已认证的短线继续接近原路点。只有原路点可安全到达且具备完整闭门让位与归位证书时才继续。
门已真实关闭并稳定后，按原指定朝向和时长驻留。

若已到达的行人站在门扇中途的扫掠区，系统先在同一室内寻找距实际到达位置不超过 `max_yield_distance_m` 的安全点，
执行 `door_close_yield`、`door_close_wait`、`door_close_return`；路点明确指定 `yaw` 时再通过 `door_close_restore` 恢复朝向。
未指定 `yaw` 的路点保留退让返回后的实际朝向，不额外恢复临时交互前推导出的运动朝向；两种情况都保留原剩余停留时间。
只有观测到真实门扇已关闭并稳定，才允许沿已验证的路段返回原到达位置；完整扫掠区保护继续生效。
这些阶段暂停原路点的转向/驻留计时，归位后继续原停留，不把临时移动或闭门等待算作指定驻留。
角色从室外获得准入并到达室内目标时，在有安全证书的情况下先完成关门和必要归位，再开始配置驻留或继续零停留路线。
已经清出扫掠区的行人可以原地等待门扇关稳。该过程单独记录为门控阶段，单纯穿过没有室内目标的门洞保留原通行授权规则。
如果原到达位置本身与关闭门扇相交，会保留安全门控并在 `door_closure.blocked` 说明原因；不会强行关闭。
若在原位置的让位预算内没有安全闭门点，则报告 `reason: no_refuge` 并保持开门，原驻留与路线继续执行。
这项可选闭门退化不适用于必需的穿门清场；实际身体碰撞、无效观测和无法安全穿门仍会明确失败。

`automaticDoor:exclusiveEntry` 是布尔元数据，默认 `true`：真实室内有住户时，新进入者排队，实际退出者优先。
公共通行门可在场景或覆盖层中显式设为 `false`；不需要在通用代码中增加门名或场景名。
直接构造 `door_specs` 的自定义调用方可设置 `exclusive_entry`；旧描述符省略此字段时保留原来的共享通行行为。

没有门元数据时本适配器为空操作。带实体碰撞的启用门在 interlock 模式下必须提供
`interiorMin` / `interiorMax`，缺少室内区域会明确拒绝；不会从名称猜房间。
当前门 schema 限米制 Z-up、直立右手且无剪切的父变换和 Z 轴转动关节，移动门铰链需重新生成外包。
这项限制独立于普通地图的米/厘米及 Y-up 转换能力。

必需穿门的退让找不到满足净空的有限安全点会明确失败。退让、物理观测和门端点均有仿真时间超时；
当前门端点预算为 `max(5 s, 标称目标斜坡时长 + 4 s)`，不是无限等待。
`opening_duration_s` / `target_ramp_duration_s` 只描述目标角度斜坡，不保证受接触影响的实际物理完成时间。
上述交互超时与 `request_timeout_s` 的 DDS 墙钟超时分别判断。

## 窄通道与有限让行

当相向角色持续互相阻挡、通道无法按原净距并排通过时，ROS 的 `passing.py` 可建立有界让行事务。
一人先转向并移到距事务起点不超过 `max_yield_distance_m` 的安全点。安全点到位后，让行者原地停留，
通行者沿经过静态、动态及身体间距验证的绕行路径继续原目标，实际通过后再释放。
它不推进原路点索引、朝向或停留，也不放宽到达容差；门协作优先，避免同一角色同时接受两个临时目标。
没有可行位置或超过事务预算会明确报错，不能用无限等待代替通行。
已认证通行路径也检查第三人的准入。保护范围覆盖预计交会结束的位置并保留余量。第三人可继续接近，
其未来 `0.9 s` 的路线将进入保护段且当前站位可安全等待时，才在原地执行 `passing_wait`。
等待者在原会车事务实际释放后恢复行走，期限和门控优先级保持。
第三人从 `passing_wait` 放行后先恢复普通行走，再参与新的会车认证。排队造成的静止不计入新会车的连续行走观察时间。
状态与 trace 的 `passing.transactions` 给出双方、阶段、安全点、起点及时间预算，便于区分让行与指定停留。
实测站位已可安全停留，且完整通过路线对该站位保留至少 `0.05 m` 的额外净空时，可直接在当前位置让行，省去走向另一个安全点的等待。
当已停步的让行者或正在低速接近墙面的让行者可以安全停在当前位置时，若已有通过路线不符合这项净空要求，系统可用该实测站位重新规划一条完整通过路线。
让行者已经退开一段距离后，若从实测站位能认证完整通路，系统可以提前结束退让。对于再退就会过度贴墙的已停步让行者，也可验证一小段足以错身的局部通路；每步重新检查双方站位和通路，受阻时只在双方能安全停留的条件下等待，错身后继续原路线。
比较同类让行点时，优先选择与静止第三人有净距余量的候选，减少到达硬净距边界前持续减速的情况。每个候选仍需通过原有的通路和扫掠检查。
对已经停步的通过者，如果其前方路径的一段与让行者剩余运动的整段扫掠保持净距，可先沿该段前进。
当前位置允许安全转向时，通过者先对准这段已验证的路径再迈步，避免偏离该段而侵入让行者的剩余扫掠空间。
每批观测重新检查地图、周围行人和动态物体。安全段用尽时等待，让行完成后继续原路线。
候选仍使用原有有限射线和完整净空/通行路径检查，优先选择可见局部路径前半平面内、身体转角较小的安全点；
只有这类候选均无法认证时才考虑向后让出，不用最终目标的隔墙直线作为前向。
接近安全点只触发检查，必须在实测身体位置下确认另一人的完整通路可行才放行；否则继续就位，
或在原退让预算内等待，`readiness_error` 说明暂未通过的通路检查。固定端点和相同几何的失败重试间隔为
`0.5 s`，身体、障碍或目标条件变化会立即重检，不重复延长退让期限。

连续行走经过零停留路点时保留行走预热时间。换路段、停留或交由更高优先级控制后，重新判断两人是否仍互相阻挡。
对于尚未进入近距离让行范围的一对行人，只有在互惠避碰邻域内、两者之间可见，且预测冲突和低速持续至少一个
`relaxation_time_s` 后，才尝试提前认证绕行。短暂减速期间仍由普通 ORCA 控制；较近的提前认证及贴近时的等待规则保持原有条件。
提前认证失败时继续普通导航。参与者实测站位发生足够变化后，允许在有限次数内重新认证，避免沿用已经过时的失败结果。
若相向双方都在显著减速，且较慢一方已经可以安全原地停留，也可提前验证完整绕行路线。
普通运动持续缺乏进展，且墙角切线方向的当前步几乎全部被地图检查截断时，允许在原转向范围内微调 ORCA 方向，仍需通过整步扫掠检查。
若他人临时占住通行者的目标区，原会车通路及其重规划均不可行，且双方站位都可安全停留，系统撤销临时会车并交回普通导航和目标排队。
近距离仍可独立认证，每个控制步最多执行一次提前认证。
两条非相向路线在近处持续汇合时，双方都低速且按原引导预测会冲突，才尝试相同的完整通路认证。
短暂减速、同向跟随或一方仍在前进时继续由普通避碰处理。候选无法认证时继续使用原控制，并保留无进展保护。

对向侧向偏置使用双方实际半径加 `pair_clearance_m`，依据原期望轨迹的预测最近距离连续衰减；
背离的角色不再加该偏置，净距充足的平行或错开路线不会仅因进入邻域就被当作对向冲突。
共享配置的行人探测范围为 `4.8 m`，配合 `2.5 s` 行人预测时域，在有预测冲突时更早产生侧向避让。
这只是打破重合路线对称性的软偏置，硬 RVO2、身体净距与整段检查仍是安全边界。
墙面软力采用连续权重，避免最近八个墙片段换序时产生突变；硬 ORCA、转向和整段净空检查继续生效。

普通避让以当前可通行路径段为前向。SFM 软偏好允许减速和侧移，不能把该段的纵向期望速度推成负值；
全向 ORCA 给出的反向速度也不直接成为原地转身目标。执行候选在 ORCA 半平面、速度上限、
当前一步可转扇区和路径前半平面内选择，旧转向锁在路径方向改变后重新校验。
反向解的前向重查询以实际路径驱动速度为目标，避免重复使用被横向墙面软力主导的偏好而陷入切向微速。
普通行走接近其他行人且受约束进度不足时，只有软偏好沿路速度也低于本次速度上限乘以
`min(1, dt / relaxation_time_s)`，才尝试恢复前进驱动，并保留原侧向惯性与让行偏置。
重查询仍服从 ORCA 与净空检查，包括安全停步。
门控和目标协调的临时指令保留原速度偏好，不由普通进展恢复覆盖。
没有可行候选时先停住，并继续检查实际下一步的静态、动态和行人扫掠净空；
这种安全停步不宣称满足整个预测时间内的全部 ORCA 半平面。协调层仍负责受限空间的通行次序。

当前路线被附近尚未到达 `start_time` 的静止行人挡住时，规划器先在临时地图中加入其身体和配置净距，尝试绕行。
路径优先保留额外净空，沿途的捷径和转角前瞻也检查静止行人的占用。起步静止的行人先在原转速限制内对齐绕行方向，再沿路径行走。
如果绕行无法获得扫掠证书，或前方行人已经开始移动，后续运动仍由原有局部避碰和执行检查控制。
前方静止行人有计划离开时，若跟随者的极低速动作几乎没有沿路线推进且趋近该人，控制器会在原地扫掠检查通过后输出 `following_wait`。
该阶段保持根位置并向原引导方向平滑转身，允许有实际进展的绕行，按下一控制步的观测重新判断。
YAML 驻留仍由路线计时。靠墙避让若整步速度射线不可通行，执行层保留达到有效速度阈值的安全前缀，再进行动态障碍和行人联合扫掠检查。

缓存路径按实际位置保留未执行部分，前方被新物体或行人挡住时重新规划，避免回选已经走过的拐点。
这些约束使用局部路径方向，不用隔墙的最终目标直线替代路径切向，也不禁止原路线返程、
用户指定的到达朝向、门关闭后的归位或已授权的有限安全让位。极小非零速度仍受朝向限制；
零速上限只允许精确零速度，避免数值残余触发突然转身。
在接触切向只差浮点量级时，单纯缩小同一条速度射线可能退化为微速停滞。
执行层会先尝试同一 ORCA 可行域内的极小向外射线，再检查原转向范围、速度、静态地图和所有受影响行人的
完整运动弦；动态检查仍在后续逐项执行。精化失败仍按原规则缩速或停步，不减小最低净距，也不推动静止行人。

## 目标占用与排队

到达、转向、驻留或完成路线的行人会保留原目标占用。来人首先检查原三维到达容差内是否还有满足身体净距的可达位置，
并检查该位置是否会堵住已到达者下一段路线的离开通道；仅凭两个目标中心距离近，不会直接禁止到达。
无兼容位置时使用 `goal_wait`，必要时由来人在固定起点 `max_yield_distance_m` 范围内执行 `goal_yield`，让出经过验证的离开通道。
行人从排他门洞出来后若须排队，优先沿前进方向走到门洞外更远的候位点。只尝试一次，且整个移动须保留身体净空、门扇扫掠空间和占用者的离开路线。
找不到合适站位或通行条件变化时，回到原有安全等待逻辑。候位点属于临时引导，原目标和停留时间仍以场景 YAML 为准。
让位搜索先复核可复用的完整物理出口路线；需要重新规划时，再检查允许范围内的多层内外圈。
每个候选必须通过原净空和完整出口证书，实际让位距离由通过检查的候选决定。
接近临时安全点后，只有实际位置的出口证书已成立才停止让位；否则仍沿原安全段继续，保持同一起点和截止时间。
离开者通过 `goal_egress` 继续原路线，实际清出后，队首通过 `goal_approach` 前往自己的原目标。
离开者改走已认证的退出段时，若原地对齐和对齐后的单步都可安全执行，会先对齐再沿该段行进。
固定朝向的下一步若会减小已满足的行人净距，则保留退出引导并使用常规避碰转向，以免卡在切线方向。
普通目标只有一名等待者时，离开者开始执行原路线的退出引导后，队首可提前前进。队首到原目标的路径及其前瞻捷径须与剩余退出通道保持配置净距。
队首先在可安全停留的实测位置对齐方向，再沿已通过检查的路径段行进，避免把局部转向带入对方的退出通道。
并行恢复的额外规划余量以实测站位的可用净空为限，路径始终须达到配置的身体净距。
整条到达路线尚未可用时，队首可先走一段有位移上限的前进路径。该段须保留离开者的整个剩余退出通道、地图及动态障碍净空。到达临时点后继续等待实际放行。
若离开引导中断，唯一等待者可在重新通过净空检查后完成已获准的短段。只有离开者近乎静止且当前可以安全停留时才允许续走；离开引导恢复后重新检查双方通路。
原目标的直达段通过同样检查时立即使用，可以在下一次栅格重规划前恢复行走。
这项检查保留原指定停留和门控优先权。退出完成时立即重新检查入场，避免沿用上一轮的重试间隔。
离开引导保留绕过所有排队者的路径，直到实测位置通过队列。若门控引导离开者从另一条路径到达下一个原始路点，
在满足该路点的三维到达容差且与旧站位保持足够净空后，也会立即释放旧占用并重新检查队首入场。
若从实测位置看不到已认证出口的剩余引导点，调度器会限频尝试重新认证到同一出口的路径，以继续引导离开者绕过自己的等待队列。
原退出段暂不可用时，允许使用仍通向同一原始目标的当前规划路径，前提是实测位置到下一段的扫掠安全。并行前进的等待者必须同时避开当前路径和保留的退出通道。
已到达者不会因排队而提前结束原停留，门扇安全让位拥有优先权，所有临时目标仍由同一 SFM/RVO2 求解及执行净空检查约束。

门内外目标交换时，已完成原停留、正等候入室者可在固定交互起点的让位距离内腾出出口。
候选位置必须同时证明退出者可到原目标、入室者随后可继续原目标；退出者实际清出后才释放入室者。
排队只延后新进入请求，保留真实退出及其有效通行授权；开门运动握手期间，目标调度不能接管或绕过门控。

普通目标交换中，若来人在配置的让位距离内无法让出完整出口，但当前位置安全、已到达者有后续路线和有限的原转向／驻留完成时刻，
来人先保持 `goal_wait`。原转向和停留全部完成后，可由原占用者在自己的固定让位范围内移动，
同时认证来人到达原目标、原占用者随后继续原路线的两条完整路径，再允许执行。
首次进入此状态即固定预计原离开时刻加原恢复预算的截止时间；后续观察不续期，也不更新退让起点。
候选优先较小位移与转角，找到首个完整证书即执行；原门口交换的选点策略保持。
缺少有限离开时刻、当前位置不安全、没有双路径证书或超时仍明确失败，不靠无限原地等待处理无解任务。
原停留已经完成并进入离开状态的占用者，按首次当前时刻固定同一恢复预算，再使用相同双路径证书流程；不再要求未来驻留提示。

运行状态和 trace 提供 `goal_occupancy.holders` / `queue` 与 `door_closure.transactions` / `blocked`。
永久占用且没有兼容到达区域的目标会报告 `permanent_goal_occupancy`；不存在安全等待点时明确报错。
仅精确相切、没有正余量的到达区域会报告 `zero_width_goal_occupancy` 并等待，避免用渐近微动伪装进展。
这类几何冲突需要调整用户场景或任务安排，系统不会修改用户路点、放宽到达容差或伪报到达。

此调度层解决有限空间的通行次序；局部速度仍参考 [SFM](https://arxiv.org/abs/cond-mat/9805244) 和
[ORCA](https://gamma-web.iacs.umd.edu/ORCA/) 的期望速度与速度约束，不将二者视为目标占用调度算法。
动态多边形先用保守分离轴判定远离，近邻仍做完整距离检查，以减少控制耗时而保持几何边界。

## 坐标地图与动画

`navigation.waypoint_frame` 显式选择出生点和路点的输入框架：

- `stage_world`：已组合的 Isaac WORLD 位置，采用源场景舞台单位/上轴；不能直接使用带父变换的 local translate。
- `world_m`：规范米制 Z-up 世界位置；省略字段的旧配置仍采用此合同。

`StageFrame` 先将 `stage_world` 规范化一次：Z-up 乘 `metersPerUnit`，
Y-up 为 `(x,-z,y) * metersPerUnit`，保持右手系；内部 actors、相机自动取景和到达判断使用规范米制计划。
`third_3` 显式选择 `stage_world`，其场景为米制 Z-up，因此原数字无需改写。
速度、到达容差、身体尺寸、地图范围/楼层和 `camera_*_m` 仍按各自 SI 合同，不随输入路点单位缩放。
ROS map 的位置/速度使用米与米每秒，yaw 使用弧度；YAML 朝向仍为度。
`origin_m` 和 `yaw_rad` 定义 `p_map = Rz(-yaw_rad) * (p_world - origin_m)`，不是像素偏移。
地图的 `origin_xy_m` 则是 cell `(0,0)` 在 ROS map 内的左下角，不能与规范世界中的 `origin_m` 混用。
`bootstrap.json` 用 `input_plans` / `world_plans` / `plans` 分别记录原输入、规范世界和 ROS map 计划；
`coordinate_contract` 记录舞台单位、上轴、map 原点/偏航。自动工作流逐点核对往返误差并导出站位图。
ROS Quaternion 字段为 **x,y,z,w**；PhysX 查询也是 XYZW，`Gf.Quatd` 构造则为 `(w, xyz)`。

地图来自真实启用的静态实体碰撞及独立地面支撑查询，不以可见模型包围盒代替空闲证据。
世界锚定、不可破坏的 FixedJoint 链可证明刚体静止；可动门、座圈和动态物体另行观测。
动态对象使用当前真实物理位姿修正的凸包及高度带，保留圆盘兼容信息；位移差分提供线速度，不宣称预测未来转动。
场景级 Observer 缓存分类拓扑，物理结构变化后失效，每帧仍读取新位姿与包围盒。

OccupancyGrid 的 cell `(0,0)` 是左下角，数据按最小 Y 行开始；PGM 图片需上下翻转。
此行列顺序依据官方 [OccupancyGrid](https://github.com/ros2/common_interfaces/blob/jazzy/nav_msgs/msg/OccupancyGrid.msg)
与 [MapMetaData](https://github.com/ros2/common_interfaces/blob/jazzy/nav_msgs/msg/MapMetaData.msg) 消息定义，
完整坐标与单位来源见[单位合同](units.md#输入路点与-ros-map)。
`-1/0/100` 分别为 unknown/free/occupied，未知格按障碍处理。PGM/YAML 是二维 XY/yaw 地图，楼层高度另在 NPZ/bootstrap 中保存。
原始地图不按身体重复膨胀；规划器按真实半径和边距检查整段运动。

角色根只有一个写入者；外部写入导致实际根位置/朝向与命令不一致时会报错。
步态相位由真实移动距离推进。低速移动时缩短步幅，并按缩短后的步幅推进周期；停止时冻结步态相位并平滑回到 Idle。源角色和动作库不保存回写。
自动门按[门元数据与协作合同](#门与导航协作)工作；适配器保留场景合成后的碰撞开关，不主动关闭门扇碰撞。

## 边界与验证

首版地图针对单层可通行平面；缺地面、陡坡、异层目标或超出地图预算会拒绝。
启动时会按原身体尺寸与原到达容差检查全部行走目标的静态路径，再创建角色和 ROS 控制进程；
这项检查不证明运行中的门状态、目标占用或多人会车一定可行。
每格有限支撑采样不能证明亚栅格孔洞安全；真正的 `UsdGeom.PointInstancer` 碰撞暂明确拒绝，普通 USD 引用实例不属于此限制。
占据目标、无会车空间、实际门状态和过窄通道仍可能导致等待或不可达；调节参数不能替代物理场景验收。
ROS 主链支持独立视口录像，使用当前 ROS 会话及公共 `recording` 配置，见[录像说明](../recording/README.md#ros-2-录像)。
录像通过同一会话观察角色状态和视口。

独立地图、角色动画、门控、求解器及真实 DDS 测试与整场景验收分开记录，命令见[测试说明](../tests/README.md)。
单项组件通过不等于当前全部用户场景通过，也不证明零停滞或任意场景优于其他控制器。

各次 GPU、场景和录像验收的环境及范围见[历史验收索引](index.md#历史验收索引)。

独立仿真使用会话自己的 Kit 时钟。Isaac Lab 任务通过 [ROS 2 训练桥](../rl/README.md) 保持任务对物理步进的所有权。旧配置迁移见[配置迁移与复用](custom_scenes.md#从旧格式迁移)。
