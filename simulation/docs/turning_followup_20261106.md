# 全片转向复审与拐角引导修正（2026-11-06）

> 本页和成片绑定验收时的三人配置。现用的四人配置见 [THIRD_3 场景](../configs/third_3/README.md)。

本轮接续用户对上一段两分钟录像的全片反馈。上一轮原生到达和碰撞检查通过，仍保留了门前反复修正和隔间拐角回摆；不能将旧通过回执解释为这些转向已经消除。

## 已复现的根因

普通路径追踪只选择完整可见的路径顶点。下一顶点被拐角遮挡时，行人继续追逐当前栅格顶点最后几毫米，甚至先横向转身；刚能看见后续顶点时又反向转回。原录像中同一业务路段的首次和下一轮进入均出现这一问题，不处于原路点指定 yaw 的转向阶段。

`NavigationEngine._corner_target` 只对附近的内部规划顶点提供下一条边上的可见引导。前瞻距离取原速度乘以松弛时间与倒数角速度的较大者；最多八次二分，所有返回捷径均通过完整圆盘与当前规划障碍检查。沿边的可见性不必单调，因此这是保守、有界的可见点搜索，不保证取得全局最远可见点。执行时仍保留 RVO2、角速度、身体净距和静态／动态完整位移段检查。

它不改变 YAML 路点、指定朝向、等待、到达容差或全局路径的业务目标。没有场景名称、行人编号或固定世界坐标分支；四个旋转地图的同型通道回归检验了方向无关性。
普通行走、目标占用准入／退出和交会通行均调用同一个 `planner._path_lookahead`；每个调用者保留自己的完整障碍、行人和预留区证书。
因此切换到 `passing_go` 或 `goal_approach` 后不会退回仅追逐精确顶点的策略。

另一根因是普通 `door_yield` 已经取得固定、安全的让位点，却继续用带横向惯性的普通点追踪，导致接近该点时反复纠偏。
现在只有整条当前位置至让位点的静态／行人净空，以及所有实测外部障碍在原剩余期限内的线性扫掠都通过时，才使用既有的先转身再沿认证线移动流程。
任何速度未知、期限非正或扫掠冲突都会保留普通 RVO 避险；不延长原期限、不改变让位起点、目标或 .4m 预算。
扫掠检查包括当前门叶，不将受控门过滤掉；后续执行检查仍逐帧验证实际障碍。

全片复核还确认了软墙力与侧步候选的组合问题：静态已经认证通行的路径旁，较强的横向壁力会改变停车转向方向；最近当前面向的侧步又可能选择几乎不前进的切向候选，导致后续折返。
现在对该认证路径只保留软墙力的正向分量，保留原SFM行人作用力和通行偏好。原RVO解已经沿路线正向且下一步位移可表示时，直接完成它的转向，不再替换为纯切向侧步。
硬地图、RVO2与静态／动态／行人完整位移段净空保持；并未移除真实墙体、缩小身体或改变角速。

关门退让后的朝向恢复也改为仅针对原路点明确指定的 `yaw`。
原先 `yaw: null` 会恢复到交互开始前推导的运动朝向，自动返程中因此出现额外大转；现在保留退让返回后的实际朝向和原剩余停留。
显式 `yaw` 的恢复位置、朝向、完整停留和运动限制仍由原公开闭环严格检查。

高频微摆的另一原因是RVO浮点线性规划的数值残余：约 `1e-8 m/s` 的结果足以触发 `atan2` 朝向更新，而位置没有有意义的改变。
现在仅对不超过请求速度上限乘以八个float32机器精度的残余，在原地下一步对动态障碍安全时归零，再通过联合扫掠传播停步；引导向量中的同尺度数值零也不作为新朝向。
联合检查可能将后车速度再次缩成残余，因此清理在完整守卫中有界传播，侧步候选后的残余也重新检查。
这是与请求速度成比例的数值处理，不是固定世界速度阈值；公开回归仍执行真实 `1e-7 m/s` 请求。

最后一类回摆来自额外恢复查询对速度阻尼的覆盖。旧逻辑在邻近行人时，只要RVO受约束输出的进度低于执行上限的25%，便改用接近满速的偏好重新查询；已有正常前进驱动的行人也因此被反复强推，停止后速度归零又改变下一帧的互惠约束。
现在这类普通交会恢复还要求软偏好沿路线的速度低于 `cap * min(1, dt / relaxation)`，只在软驱动确实受压制时介入。
已有有效驱动但被硬避碰限制的情形保留正常阻尼。原负向恢复、近目标恢复和切向脱困仍保留，并由旧回归验证。
该条件来自原控制步长与松弛时间，没有场景坐标或新配置阈值。

## 局部因果验证

独立分析从旧录像逐步重放至检查点，位置、朝向、速度和业务上下文与旧命令完全一致，再仅替换拐角引导进行自反馈闭环。两次同型路段均改善：

所有静态、动态和行人完整位移段检查均未发现违例。原有业务转身和门控仍计入全阶段统计。局部重放保留旧外部障碍／门观测，因此仅证明局部因果，不能代替新时序下的完整原生运行。

独立紧凑直角通道回归同时检查实际到达、累计额外转角、完整静态扫掠、速度／角速限制、身体朝向与非零速度一致以及原计划不被改写。四个旋转方向均通过；恢复旧顶点追踪后四个方向均失败。

旧录像首个门前让位快照的闭环中，有效方向反复从四次降至零次，额外绝对转角从53.65°降至约 .000059°，请求开门由5.733秒提前至4.467秒。
单独构造的来袭移动墙反例中，条件认证拒绝强制射线，保留原控制器逐值相同的安全逃逸速度。
此前无条件强制射线会失去这一逃逸能力，因此不采用无条件方案。

另一个独立单人用例中，原目标与起点之间的整个身体圆盘路径已经畅通，仅旁边存在墙体。旧实现累计转向268.71°，修正后172.46°，所需初始最短转角约164.8°；四个旋转方向均验证旧版失败、新版通过。
关闭横向软墙偏好不代表删除墙体硬约束，测试仍逐步验证实际身体完整扫掠、速度、角速、非零运动朝向、原目标实际到达和原计划不变。

完整运行结果以本轮新输出目录中的最终回执为准；旧录像和旧报告继续保留原始证据边界。

## 中间原生运行

`tests/output/turning_followup_20261106/native120` 是中间失败记录：原生运行至约84秒时，普通两人交会未找到 .4m 内可认证让位点而明确退出。
该次源码、输入未漂移，清理三项通过；其到达／安全前缀不能当作完整120秒通过。
这一失败需要独立修正通行协调，不能扩大让位预算、缩小净距或仅调整场景时序绕过。

失败快照证实，第三人暂时覆盖了完整路线上的一个通道截面；只提高局部让位角度／距离采样密度也不能取得完整路线证书。
新的有界证书等待仅在去除已知正在行走的第三人后，同一对行人可以认证完整原目标路线、且两人实际站位可以安全静止时启用。
等待沿首次堵塞时刻固定截止时间，不续期；第三人保留原路线。实际全体仍参与原证书重查，完整证书恢复后才启动正式交易，同帧保护其通行路线。
未知速度、静止或高优先级第三人不作为暂态封路证明；两人自身封闭无解仍明确失败。超时、原上下文变化、控制优先级和安全站位变化分别有公开回归。
真实快照公开闭环已经验证等待后交换成功，最小净距 .25m、最大让位约 .394m；仍须以新完整原生运行作为最终验收。

`native120_v2` 在14.6秒因交会控制仍精确追逐剩余约2mm的中间顶点而触发门准入超时。
只替换Passing共享前瞻后，同一真实13秒检查点继续通过原期限；没有延长门准入时间。

`native120_v3` 和 `recording120` 的业务、物理、坐标与清理流程通过，但全片质量复核仍发现约106.67–107.20秒的实际回摆。
该段位移可表示、速度约 .05–.11m/s，不能用微速度数值残余或业务指定朝向解释。
对应录像在 `recording120/quality_review.json` 标记为诊断证据；不作为最终转向修复交付。

从该次106.5秒的精确状态仅替换恢复条件，实际闭环的有效方向反向从10次降至1次，低于 .05m/s 的转角从39.88°降至0°，两秒行程从 .676m增至1.067m，所有物理证书通过。
剩余一次由向南行进转为沿下一条边向西南行进，前后分别实际移动 .601m和 .466m，没有原地反打。
67.5秒与11.5秒的独立检查点在该条件下输出不变；全删旧恢复会导致既有切向脱困回归，因此未采用全删方案。

`native120_v4` 保留了转向改善，但96.45秒仍因一对行人漏触发通行协调而违反原12秒进度预算，不能算通过。

旧预测认为两人方向夹角不足以相向，新预测与实际一致，确认了真正的冲突；不是提高冲突阈值或扩大预算即可合理解决的问题。
预测器现也使用同一前瞻、身体半径、速度／松弛时间和当前非受控规划障碍。
公开独立遮挡场景及真实缓存回归分别验证旧版失败、新版通过，并保留受控门归属的负例。
